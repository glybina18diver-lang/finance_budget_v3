# История версий — Finance Budget

Все значимые изменения документируются в этом файле.  
Формат основан на [Keep a Changelog](https://keepachangelog.com/).  
Версионирование — [Semantic Versioning](https://semver.org/lang/ru/).

> ⚠️ **Примечание:** Все версии `0.x.y` являются нестабильными и предназначены только для внутренней разработки.

---

## [v0.13.1] - 2026-08-10

### Добавлено
- Просмотр детальной информации по выбранной транзакции.
- Фильтрация операций по дате, типу и категориям.
- Поддержка множественного выделения транзакций с помощью клавиши `Shift`.
- Автодополнение при вводе контрагентов.
- Базовая функция создания возврата транзакции.

### Изменено
- В комбобоксах выбора категорий (новые операции, фильтры) теперь отображается иерархическое дерево.
- Улучшена логика поиска и создания контрагентов для исключения дубликатов в базе данных.

### Исправлено
- Устранена критическая ошибка `UNIQUE constraint failed` при работе с контрагентами.

---

## [v0.13.0] - 2026-08-07

### Добавлено
- Возможность дублирования транзакций с гибкими настройками копирования.
- Функция редактирования уже созданных транзакций.
- Новые визуальные темы `NEON_THEME`, `DARK_THEME`, `LIGHT_THEME` и обновлённое оформление главного окна.
- Поддержка сортировки данных в большинстве таблиц приложения.
- Масштабное обновление интерфейса: внедрены QSS-стили по темам для кнопок, вкладок (`QTabWidget`), групп элементов (`QGroupBox`) и таблиц данных.

### Изменено
- Улучшен внешний вид гистограммы доходов и расходов.
- Улучшена визуальная структура диалогов и окон приложения.

---

## [v0.12.1] - 2026-08-01

### Добавлено
- Теперь показывает рузультат платежа по кредитке
- Счета в главном окне отбражаются

## [v0.12.0] - 2026-07-29

### Добавлено
- Диалоги внесения платежей по кредитам и кредитным картам.
- Фильтрация операций в диалоге переводов.
- Контекстное меню для транзакций с возможностью удаления через правый клик или клавишу `Delete`.
- Минимальный график доходов и расходов в главном окне приложения.
- Автоматический расчёт даты окончания кредита на основе указанного срока в UI.

### Изменено
- Оптимизирована загрузка и отображение списков счетов и категорий: в интерфейсе теперь видны только пользовательские элементы, системные записи скрыты.
- Переработана логика расчёта итоговых сумм при добавлении транзакций.
- Улучшен интерфейс диалогов переводов и добавления операций (расположение элементов, валидация полей ввода).
- Обновлена логика загрузки данных в диалог операций: загрузка всех записей из БД с фильтрацией системных элементов только для комбобоксов.

### Исправлено
- Устранены ошибки валидации при создании кредитов и займов.
- Исправлена некорректная обработка типов данных (`str`/`Decimal`) при создании финансовых операций.
- Восстановлено корректное обновление таблиц и полей выбора после закрытия дочерних окон.

## [v0.11.0] - 2026-07-22

### Изменено
- Внутренние финансовые расчёты полностью переведены на тип `Decimal` для обеспечения точности и исключения ошибок округления.
- В списке счетов теперь отображаются только пользовательские счета, системные и технические записи скрыты.
- Технические идентификаторы типов счетов в интерфейсе заменены на понятные пользовательские названия (в комбобоксах и таблицах).
- Обновлён интерфейс загрузки и отображения займов и кредитов.

### Исправлено
- Устранены ошибки и нестабильность, возникшие после интеграции модуля кредитов.

## [v0.9.0-alpha]  - 2026-07-18

- Отказ от сложной [модели кредиток](docs\Концептуальная_модель_кредитной_карты_Сбер_Молодежная.md) так как ее сложно релизавть данные все равно разойдутся с банковскими (чтоб не расходились нужны подключать баноквский API, а в РФ такого нет тем более для физ.лиц) и потому осуществляется переход на более простую модель где нет сложных расчетов и где ползователь сам пишет проценты/комисии и сумму платежа (см. [простая модель](docs\Простая_модель_кредиток.md)).
- Для этой версии выпускается бинарник как есть

## [v0.8.0] - 2026-07-16

### Добавлено
- Диалог создания кредитных карт на основе новой [концептуальной модели](docs\Концептуальная_модель_кредитной_карты_Сбер_Молодежная.md).

### Изменено

- Оптимизирован репозиторий счетов: методы разделены на получение всех счетов, только активных и фильтрацию по типу.
- Внесены улучшения в интерфейс и поведение диалогов управления кредитными картами.

### Исправлено
- Устранена критическая ошибка создания транзакций: метод теперь корректно возвращает `transaction_id` вместо объекта курсора БД.
- Исправлены сопутствующие ошибки сохранения и обновления данных.

## [v0.7.6] - 2026-07-10

### Добавлено
- Сквозное логирование операций в файл для упрощения диагностики.
- Обработка исключений `try-except` во всех критических методах с записью деталей в лог.

- Архитектура обработки ошибок приведена к единому стандарту с автоматическим логированием.

### Исправлено
- Устранена ошибка загрузки данных в `CreditCardDialog`: исправлено имя вызываемого метода в `_get_active_accounts_as_dicts` в репозитории счетов.
- Исправлена логика расчётов после создания платежа: запись в БД теперь корректно инициирует последующие вычисления.

## [v0.7.5] - 2026-07-10

## [v0.7.4] - 2026-07-09

### Добавлено
- Реализован `CreditCardDialog` для управления кредитными картами с отдельным окном конфигурации параметров.
- Логика миграций базы данных вынесена в изолированный модуль `core/migration.py`.
- Внедрена проверка на связанные транзакции при операциях со счетами.

### Изменено
- **Рефакторинг модели `Account`:** Поля, специфичные для кредитных карт, удалены из общей таблицы счетов. Параметры кредиток теперь вынесены в отдельный диалог, в интерфейсе управления счетами оставлена только навигационная подсказка.
- Обновлена логика инициализации и открытия диалога добавления платежа (`AddPaymentDialog`).

### Исправлено
- Устранена ошибка, при которой кредитные карты не подгружались при инициализации `CreditCardDialog`.
- Реализован временный обход ограничения `FOREIGN KEY constraint failed` на уровне UI: теперь система требует явно удалять запись из таблицы `credit_cards` через специализированный диалог перед удалением самого счёта. *(Полное решение на уровне СУБД запланировано в следующих версиях)*
